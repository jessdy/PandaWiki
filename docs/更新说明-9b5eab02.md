## 二、本版本变化

### 安全修复（2026-11-11 三份扫描报告）

- **Share 前台**：跨站请求校验（带跨站 Origin 一律拒绝，写操作缺 Origin 时校验 Referer）；CORS 只回显同域 Origin；咨询列表 `status` 参数校验；数据库/网络/路径类错误原文不再返回给客户端
- **管理端登录态**：JWT 改为 HttpOnly Cookie（`panda_wiki_token`），删除登录密码日志，对比弹窗 XSS 过滤
- **Cookie**：会话 Cookie 默认 `Secure` + `SameSite=Lax` + 会话级（关闭浏览器失效）
- **响应头**：前台下发 CSP、`X-Content-Type-Options`、`Referrer-Policy`；去掉 `X-Powered-By`、`X-Middleware-*`、`x-current-path`
- **其他**：LDAP 过滤转义；Share 上传校验文件头；Discord token 不再写日志；遥测默认关闭（需 `TELEMETRY_ENABLED=true`）；docker-compose 不再写死 MinIO 账号

逐项对照见 `docs/202061111-report(1)/修复说明-20261112.md`。

### TGT 登录

- 权限校验请求 `generalArgument` 中的 `id` 改为 `userId`：
  ```json
  {"generalArgument":{"ip":"...","loginName":"...","userId":168},"jsonArg":{"permissions":["100000:function:kfsuser"]}}
  ```
- 请求体改为强类型结构，`loginName` 白名单校验，`tgt` 限制长度
- 认证平台地址仍在管理后台「系统配置 → 平台地址」配置

### 雳鉴 IAST 插桩并入普通版

- 不再区分 `prod` / `prod-iast` 镜像；api、consumer 镜像同时包含普通版和插桩版
- 开关文件 `data/conf/iast/iast.conf`：`IAST_ENABLED=true/false` + 雳鉴 IP/端口，改后重建 api/consumer 生效
- 开关为 true 但 IP 未填对时以普通版启动并打印错误，不影响业务

### JWT 密钥轮换

- 新增 `PREVIOUS_JWT_SECRET`：更换 `JWT_SECRET` 时填旧值，仅用于解密/校验旧数据

## 三、现场更新步骤

已在运行本系列版本（compose 中已有 `./data/conf/iast` 挂载）的机器：

```bash
cd /opt/panda-wiki
D=$(date +%Y%m%d%H%M)
for s in api consumer app nginx; do docker tag panda-wiki-$s:prod panda-wiki-$s:prod-bak-$D 2>/dev/null || true; done

sha256sum panda-wiki-images-9b5eab02-arm64.tar.gz      # 与上表一致
gunzip -c panda-wiki-images-9b5eab02-arm64.tar.gz | docker load

docker compose up -d --no-build --pull never --force-recreate nginx app api consumer
```

从更早版本（11 月 10 日前、或 `prod-iast` 插桩版）升级，还需修改 docker-compose.yml 和 .env，按 **[升级说明-20261112](./升级说明-20261112.md)** 操作。

## 四、验证

```bash
docker compose ps nginx app api consumer
docker logs panda-wiki-api 2>&1 | head -1          # IAST: ... 以普通版/插桩版启动
docker logs panda-wiki-api 2>&1 | grep -iE "caddy|level=ERROR" | tail -5
curl -sI http://127.0.0.1:<前台端口>/ | grep -iE "x-powered-by|content-security|x-content-type|referrer"
```

- 管理端、前台可打开；所有用户需重新登录
- 前台响应头含 `Content-Security-Policy`、`X-Content-Type-Options`、`Referrer-Policy`，无 `X-Powered-By`
- TGT：访问 `/auth/login?tgt=<令牌>` 可登录
- 前台若有图片/视频/嵌入页面被浏览器拦截（CSP），反馈具体来源后调整

## 五、回滚

```bash
for s in api consumer app nginx; do docker tag panda-wiki-$s:prod-bak-<时间> panda-wiki-$s:prod; done
docker compose up -d --no-build --pull never --force-recreate nginx app api consumer
```

## 六、以后在 106 上构建

源码目录 `/opt/build/PandaWiki`，基础镜像（golang、openEuler、node、nginx 的 arm64 版）已在本机。

```bash
# 本地同步代码（不传 .git、node_modules、数据和安装包）
rsync -az --delete --exclude .git --exclude node_modules --exclude dist/ --exclude /data/ \
  --exclude /packages/ --exclude /panda-wiki-iast-deploy/ --exclude '*.tar.gz' --exclude '*.7z' \
  --exclude .env ./ root@47.110.246.106:/opt/build/PandaWiki/

# 106 上构建
cd /opt/build/PandaWiki
VERSION=<git 提交号> scripts/build-images.sh                       # 只构建
VERSION=<git 提交号> scripts/build-images.sh --deploy /opt/panda-wiki   # 构建并更新本机
VERSION=<git 提交号> scripts/build-images.sh --save /opt/packages/panda-wiki-images-<版本>-arm64.tar.gz
scripts/build-images.sh --only api,consumer                       # 只构建部分镜像
```

- 后端（含插桩版）约 5 分钟，前端约 10 分钟
- 插桩编译器 `backend/iast/go-active-linux-arm64` 不入 git，需单独放到构建目录（已放好）
- 106 访问不了 Docker Hub 和 proxy.golang.org；脚本默认使用 goproxy.cn、npmmirror、阿里云 apk 源
- 每次构建会把旧镜像备份为 `*:prod-bak-<时间>`，磁盘（40G）紧张时定期清理旧备份和 `docker builder prune`
- 前端编译需较多内存（默认给 Node 4G 堆，`NODE_HEAP_MB` 可调）
