## 二、本版本主要变化

### 启明星辰扫描
- 删除入库私钥；管理端 JWT Cookie `Path=/api`、`SameSite=Strict`
- 其余多为误报确认（国密 Seal、`io.Copy`、配置键名等）

### 红网测评扫描
- Mermaid XSS：`strict` + DOMPurify
- 云鉴权默认 HTTPS；TGT/UserLink/GitHub 登录失败锁定
- JWT 增加 `role` 声明并与库角色比对
- 审计白名单大幅补齐；验证码重新启用；HSTS / 日志脱敏 / EPUB·UploadImage 校验等
- 详见两份修复列表

### 插桩
- 仍并入普通版镜像；`data/conf/iast/iast.conf` 开关

## 三、现场更新步骤

```bash
# 1. 加载镜像
docker load -i panda-wiki-images-6120d378-arm64.tar.gz

# 2. 进入部署目录（示例 /opt/panda-wiki）
cd /opt/panda-wiki

# 3. 确认 .env：JWT_SECRET 长度 ≥ 32；内置管理员口令满足复杂度
#    云鉴权若仅填 IP/端口，将默认按 https 访问

# 4. 重建业务容器（中间件不变）
docker compose up -d --no-build --pull never --force-recreate nginx app api consumer

# 5. 验证
docker logs panda-wiki-api 2>&1 | head -5
# 管理端重新登录（新 JWT 才带 role）
```

若 compose 尚无插桩挂载，对照包内 `docker-compose.yml` 或 `docs/升级说明-20261112.md` 补齐后重建。

## 四、回滚

构建机/现场若保留了 `prod-bak-*` 标签：

```bash
docker tag panda-wiki-api:prod-bak-XXXX panda-wiki-api:prod
# consumer / app / nginx 同理
docker compose up -d --no-build --pull never --force-recreate nginx app api consumer
```

## 五、注意

1. `JWT_SECRET` &lt; 32 字符将无法启动  
2. 内置三员口令若不符合复杂度：启动时打 ERROR 并跳过写入（不阻断服务）；请尽快改为强口令  
3. 评论/上传/问答需验证码  
4. 插桩开启方法见 `现场部署与插桩说明.md` / `iast/iast.conf.example`
