# 升级说明（2026-11-12）

适用于从 11 月 10 日前后的版本（含 `prod-iast` 插桩版）升级到本版本。本版本包含 2026-11-11 三份安全扫描报告的修复，并把雳鉴 IAST 插桩并入普通版镜像。

## 一、需要更新的镜像

| 镜像 | 是否更新 | 主要变化 |
| --- | --- | --- |
| `panda-wiki-api:prod` | **是** | 安全修复（Share 跨站请求校验、数据库错误不外泄、TGT 登录参数强类型 + 权限校验改用 `userId`、管理端 JWT 改 HttpOnly Cookie、LDAP 注入、上传文件头校验等）；Caddy 前台路由删除多余响应头；遥测默认关闭；支持 `PREVIOUS_JWT_SECRET`；内置插桩版二进制 |
| `panda-wiki-consumer:prod` | **是** | 内置插桩版二进制；支持 `PREVIOUS_JWT_SECRET` |
| `panda-wiki-app:prod`（前台） | **是** | CSP / nosniff / Referrer-Policy 响应头；去掉 `X-Powered-By`、`x-current-path`；`x-pw-session-id` 改会话级 Cookie |
| `panda-wiki-nginx:prod`（管理端） | **是** | 登录态改 HttpOnly Cookie、对比弹窗 XSS 过滤、去掉登录日志、默认地址改 https |
| caddy、postgres、redis、minio、nats、qdrant、crawler、raglite | 否 | 沿用现有镜像 |

不再需要 `panda-wiki-api:prod-iast`、`panda-wiki-consumer:prod-iast` 和 `docker-compose.iast.yml`。

镜像只有 arm64 版包含插桩版二进制；x86 版功能相同，只是无法开启插桩。

## 二、docker-compose.yml 修改

可直接使用源码中的 `docs/production-restore/docker-compose.yml`（arm 部署用 `arm/docker-compose.yml`）。手工修改时按下表逐项改：

### api 服务

```yaml
  api:
    volumes:
      # ...原有挂载保留
      - ./data/conf/iast:/iast-config:ro                    # 新增
    environment:
      # ...原有变量保留
      - IAST_CONFIG_FILE=/iast-config/api.toml              # 新增
      - IAST_AGENT_TAG=panda-wiki-api                       # 新增
      - S3_ACCESS_KEY=${S3_ACCESS_KEY:?S3_ACCESS_KEY is required}   # 原为 ${S3_ACCESS_KEY:-s3panda-wiki}
      - PREVIOUS_JWT_SECRET=${PREVIOUS_JWT_SECRET:-}        # 新增，放在 DATA_ENCRYPTION_KEY 后
```

### consumer 服务

```yaml
  consumer:
    environment:
      - IAST_CONFIG_FILE=/iast-config/consumer.toml         # 新增
      - IAST_AGENT_TAG=panda-wiki-consumer                  # 新增
      - S3_ACCESS_KEY=${S3_ACCESS_KEY:?S3_ACCESS_KEY is required}   # 原为 ${S3_ACCESS_KEY:-s3panda-wiki}
      - PREVIOUS_JWT_SECRET=${PREVIOUS_JWT_SECRET:-}        # 新增
    volumes:
      - ./data/conf/iast:/iast-config:ro                    # 新增
```

### 其他服务（去掉写死的 MinIO 账号）

| 服务 | 原值 | 改为 |
| --- | --- | --- |
| minio | `MINIO_ACCESS_KEY=s3panda-wiki` | `MINIO_ACCESS_KEY=${S3_ACCESS_KEY:?S3_ACCESS_KEY is required}` |
| crawler | `OSS_MINIO_ACCESS_KEY=s3panda-wiki` | `OSS_MINIO_ACCESS_KEY=${S3_ACCESS_KEY:?S3_ACCESS_KEY is required}` |
| raglite | `STORAGE_MINIO_ACCESS_KEY_ID=s3panda-wiki` | `STORAGE_MINIO_ACCESS_KEY_ID=${S3_ACCESS_KEY:?S3_ACCESS_KEY is required}` |

### caddy 服务（确认即可）

```yaml
      - "CADDY_ADMIN=unix//var/run/caddy/caddy-admin.sock|0666"
```

旧版只在 `docker-compose.iast.yml` 里有 `|0666` 的，要补到主 compose。

### 镜像 tag

api / consumer 的 `image` 用 `:prod`。若 `.env` 里有 `API_IMAGE_TAG=prod-iast`、`CONSUMER_IMAGE_TAG=prod-iast`，删除或改为 `prod`。

## 三、.env 修改

| 变量 | 要求 |
| --- | --- |
| `S3_ACCESS_KEY` | **必填**。compose 不再有默认值，未设置会拒绝启动。原来用默认值的，填 `S3_ACCESS_KEY=s3panda-wiki`（须与 MinIO 现有用户名一致，否则文件读不出来） |
| `JWT_SECRET` | 建议换成 `openssl rand -hex 32` 生成的 64 位值（低于 32 位启动会告警） |
| `PREVIOUS_JWT_SECRET` | 更换 `JWT_SECRET` 时**必须**填旧值，用于解密旧数据；不换则不填 |
| `TELEMETRY_ENABLED` | 不填（遥测默认关闭） |
| `COOKIE_SECURE` | 生产环境不要设为 `false` |

更换 JWT_SECRET 的命令：

```bash
OLD=$(grep '^JWT_SECRET=' .env | cut -d= -f2-)
cp .env .env.bak-$(date +%Y%m%d%H%M)
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -hex 32)|" .env
grep -q '^PREVIOUS_JWT_SECRET=' .env || echo "PREVIOUS_JWT_SECRET=$OLD" >> .env
```

## 四、插桩开关文件

```bash
mkdir -p data/conf/iast
cp iast.conf.example data/conf/iast/iast.conf     # 模板在源码 docs/iast/iast.conf.example
```

```bash
IAST_ENABLED=false          # true 开启插桩
IAST_SERVER_IP=改成雳鉴IP
IAST_SERVER_PORT=8888
```

原来的 `data/conf/iast/api.toml`、`consumer.toml` 可以保留；开关为 true 时优先使用它们。详见 `docs/update-operation.md`。

## 五、升级步骤

```bash
cd /opt/panda-wiki

# 1. 备份
D=$(date +%Y%m%d%H%M)
cp docker-compose.yml docker-compose.yml.bak-$D
cp .env .env.bak-$D
for s in api consumer app nginx; do docker tag panda-wiki-$s:prod panda-wiki-$s:prod-bak-$D 2>/dev/null || true; done

# 2. 加载新镜像
gunzip -c panda-wiki-images.tar.gz | docker load

# 3. 按第二、三、四节修改 docker-compose.yml、.env、data/conf/iast/iast.conf
docker compose config -q && echo COMPOSE_OK

# 4. 重建（caddy 一起重建以应用 socket 权限；minio/crawler/raglite 变量值未变可不重建）
docker compose up -d --no-build --pull never --force-recreate caddy nginx app api consumer
```

## 六、验证

```bash
docker logs panda-wiki-api 2>&1 | head -1        # IAST: ... 以普通版/插桩版启动
docker logs panda-wiki-api 2>&1 | grep -iE "caddy|level=ERROR" | tail -5
curl -sI http://127.0.0.1:<前台端口>/ | grep -iE "x-powered-by|content-security|x-content-type|referrer"
```

- 前台响应头应有 `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Referrer-Policy`，没有 `X-Powered-By`
- 管理端、前台可正常打开；**所有用户需重新登录**（登录态改为 Cookie；如更换了 JWT_SECRET 旧令牌也会失效）
- 管理端需与 API 同源访问，Cookie 才生效
- TGT 登录：后台「系统配置 → 平台地址」需已配置认证平台 IP/端口
- 前台若有图片、视频或嵌入页面被浏览器拦截（CSP），在 `web/app/next.config.ts` 的 `contentSecurityPolicy` 中补充来源后重新构建 app

## 七、回滚

```bash
cp docker-compose.yml.bak-<时间> docker-compose.yml
cp .env.bak-<时间> .env
for s in api consumer app nginx; do docker tag panda-wiki-$s:prod-bak-<时间> panda-wiki-$s:prod; done
docker compose up -d --no-build --pull never --force-recreate caddy nginx app api consumer
```

本版本没有不可逆的数据库结构变更，回滚只需恢复镜像、compose 和 `.env`。`.env` 必须与镜像一起恢复：更换过 `JWT_SECRET` 时，旧镜像不认识 `PREVIOUS_JWT_SECRET`，只用当前 `JWT_SECRET` 解不开早期用它加密的数据。
