# PandaWiki 离线整机迁移说明

把当前正在运行的一套 PandaWiki（含镜像、业务库、对象存储与向量数据）打包后，部署到另一台 **同 CPU 架构** 的 Linux 机器。

本说明对应离线包目录（示例）：

```text
panda-wiki-offline-YYYYMMDD/
├── ARCH.txt                 # 源机架构，目标机必须一致（如 aarch64）
├── docker-compose.yml
├── .env                     # 密码与密钥，迁移后不要改
├── panda-wiki-images.tar.gz # 全部 Docker 镜像
├── panda-wiki.dump          # 主库 panda-wiki
├── raglite_v2.dump          # 检索库 raglite_v2（问答/向量元数据）
├── panda-wiki-files.tar.gz  # MinIO / Qdrant / Caddy / 证书等
└── 离线整机迁移说明.md      # 本文件
```

## 目标机要求

- Linux，Docker 20+，已安装 `docker compose`（v2）
- CPU 架构与 `ARCH.txt` 一致（当前包为 **ARM64 / aarch64**）
- 磁盘建议预留 **≥ 25GB** 空闲（镜像解压后约十余 GB）
- 开放后台端口（`.env` 里的 `ADMIN_PORT`，当前多为 `32768`）及站点端口（Caddy host 网络，常见 `8038` 等，以原站配置为准）

## 包内文件说明

| 文件 | 作用 |
| --- | --- |
| `panda-wiki-images.tar.gz` | 自研 `:prod` 镜像 + Postgres/Redis/MinIO/NATS/Qdrant/Caddy/crawler/raglite |
| `panda-wiki.dump` | 主业务库逻辑备份 |
| `raglite_v2.dump` | raglite 库；缺失会导致检索服务反复跑迁移并卡在 Qdrant 鉴权 |
| `panda-wiki-files.tar.gz` | `data/` 下 minio、qdrant、raglite、conf、nginx/ssl、caddy |
| `.env` | 与源机相同的密钥；已写入库和对象存储，**禁止随意更换** |

Redis、NATS 为缓存与队列，不单独迁移。

**不要改**的关键项：`POSTGRES_PASSWORD`、`S3_SECRET_KEY`、`S3_ACCESS_KEY`、`QDRANT_API_KEY`、`JWT_SECRET`、`NATS_PASSWORD`、`REDIS_PASSWORD`、`DATA_ENCRYPTION_KEY`。

三员相关：`SECURITY_ADMIN_PASSWORD`、`AUDIT_ADMIN_PASSWORD` 可按需保留；首次启动若库中尚无对应账号会按策略创建。

## 一、放到目标机

```bash
sudo mkdir -p /opt/panda-wiki
# 将离线包全部文件拷到 /opt/panda-wiki
cd /opt/panda-wiki
```

## 二、加载镜像并解压文件

```bash
gunzip -c panda-wiki-images.tar.gz | docker load

mkdir -p data
tar -C data -xzf panda-wiki-files.tar.gz

# Postgres 必须空目录首次初始化，再导入 dump
rm -rf data/postgres
```

此时不要直接 `up` 全部服务。

## 三、初始化主库并导入

```bash
docker compose up -d --no-build --pull never postgres

# 等到 accepting connections
docker compose exec postgres pg_isready -U panda-wiki -d panda-wiki

docker cp panda-wiki.dump panda-wiki-postgres:/tmp/panda-wiki.dump
docker exec panda-wiki-postgres pg_restore -U panda-wiki -d panda-wiki \
  --clean --if-exists --no-owner /tmp/panda-wiki.dump
```

`pg_restore` 可能有部分对象已存在的提示，可忽略。确认：

```bash
docker exec panda-wiki-postgres psql -U panda-wiki -d panda-wiki \
  -c "SELECT count(*) AS users FROM users; SELECT count(*) AS nodes FROM nodes;"
```

## 四、导入 raglite_v2（必做）

```bash
docker exec panda-wiki-postgres psql -U panda-wiki -d postgres -tc \
  "SELECT 1 FROM pg_database WHERE datname='raglite_v2'" | grep -q 1 || \
  docker exec panda-wiki-postgres psql -U panda-wiki -d postgres \
  -c 'CREATE DATABASE raglite_v2 OWNER "panda-wiki";'

docker cp raglite_v2.dump panda-wiki-postgres:/tmp/raglite_v2.dump
docker exec panda-wiki-postgres pg_restore -U panda-wiki -d raglite_v2 \
  --clean --if-exists --no-owner /tmp/raglite_v2.dump || true
```

## 五、启动整套

```bash
docker compose up -d --no-build --pull never
docker compose ps
```

不要执行 `docker compose down -v`（会删掉 `data/` 挂载内容）。

若 `raglite` 先于 stream 创建而 `consumer` 短暂重启，等 raglite 起来后通常会自行恢复；仍异常可：

```bash
docker compose restart consumer
```

## 六、验收

- `docker compose ps` 各容器为 Up
- 管理后台：`https://<目标机IP>:<ADMIN_PORT>/`（证书多为自签，浏览器需信任或跳过）
- 用源机同一管理员账号登录，能看到原用户与文档
- 站点由 Caddy（`network_mode: host`）对外提供，端口以原 `data/caddy` 配置为准
- 搜索/问答有结果；若为空，优先检查 `data/qdrant` 是否解压完整，以及 `raglite_v2` 是否已导入

## 导入失败时只重做 Postgres

保留已解压的 MinIO、Qdrant 等文件：

```bash
docker compose stop postgres
rm -rf data/postgres
docker compose up -d --no-build --pull never postgres
# 再按第三节、第四节重新 pg_restore
```

## 源机如何重新打包装包（备查）

在运行中的源机部署目录（如 `/opt/panda-wiki`）：

```bash
docker compose stop api consumer raglite crawler

docker exec panda-wiki-postgres pg_dump -U panda-wiki -d panda-wiki -Fc -f /tmp/panda-wiki.dump
docker exec panda-wiki-postgres pg_dump -U panda-wiki -d raglite_v2 -Fc -f /tmp/raglite_v2.dump
docker cp panda-wiki-postgres:/tmp/panda-wiki.dump ./panda-wiki.dump
docker cp panda-wiki-postgres:/tmp/raglite_v2.dump ./raglite_v2.dump

tar -C data -czf panda-wiki-files.tar.gz minio qdrant raglite conf nginx/ssl caddy

docker compose start api consumer raglite crawler

docker save \
  panda-wiki-api:prod \
  panda-wiki-consumer:prod \
  panda-wiki-app:prod \
  panda-wiki-nginx:prod \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/postgres-zhparser:17.6-bookworm \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/panda-wiki-redis:7.4.2-alpine \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/panda-wiki-minio:RELEASE.2025-04-22T22-12-26Z-cpuv1 \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/panda-wiki-nats:2.11.3-alpine \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/panda-wiki-qdrant:v1.14.1 \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/panda-wiki-caddy:2.10-alpine \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/anydoc:v0.7.1 \
  chaitin-registry.cn-hangzhou.cr.aliyuncs.com/chaitin/raglite:v2.8.5 \
  | gzip > panda-wiki-images.tar.gz
```

将上述文件与 `.env`、`docker-compose.yml` 一并拷走即可。
